## Топология

Лабораторная работа выполняется в симуляторе. Схема с устройствами и кабелями открывается по адресу лаборатории; нажмите на коммутатор на схеме, чтобы открыть его консоль. Щелчок по компьютеру или серверу открывает окно устройства; на его «Рабочем столе» есть «Командная строка», «IP-конфигурация», «Веб-браузер» и другие приложения.

| Кабель | Устройство | Порт | Устройство | Порт |
|---|---|---|---|---|
| Медный | MultiServer | F0 | Switch | F0/5 |
| Медный | HTTP-Client | F0 | Switch | F0/1 |
| Медный | FTP-Client | F0 | Switch | F0/2 |
| Медный | E-Mail-Client | F0 | Switch | F0/3 |
| Медный | DNS-Client | F0 | Switch | F0/4 |

Все устройства уже настроены. MultiServer (192.168.1.254) отдает веб-страницу и отвечает на DNS-запросы об имени **multiserver.nsalab.local**; клиенты HTTP-Client, FTP-Client, E-Mail-Client и DNS-Client (192.168.1.1–192.168.1.4) используют его как DNS-сервер. Служб FTP и электронной почты в симуляторе пока нет, поэтому FTP-Client и E-Mail-Client только присутствуют на схеме, а шаги с ними в этой лабораторной работе не выполняются.

## Задачи

Часть 1. Генерация сетевого трафика в режиме «Симуляция»

Часть 2. Изучение функциональных возможностей протоколов TCP и UDP

## Общие сведения

Это упражнение по моделированию позволит понять основы протоколов TCP и UDP для более подробного их изучения в дальнейшем. Режим «Симуляция» дает возможность просматривать состояние различных PDU, когда они перемещаются по сети.

Описанные ниже шаги проведут вас через процесс запроса сервисов с помощью приложений, доступных на клиентском ПК. Вы изучите функциональные особенности протоколов TCP и UDP, мультиплексирования и функции номеров портов при определении локального приложения, запросившего или отправляющего данные.

## Инструкции

### Часть 1. Генерация сетевого трафика в режиме «Симуляция» и просмотр мультиплексирования

**Шаг 1. Сгенерируйте трафик для заполнения таблиц протокола разрешения адресов (ARP).**

Уменьшите объем сетевого трафика, отображаемого при моделировании. Этот шаг выполняется в режиме «Лаборатория», в котором лабораторная работа открывается.

1.  Нажмите на **MultiServer** на схеме: откроется окно устройства. На «Рабочем столе» выберите «Командная строка» (приглашение `C:\>`).

2.  Введите команду **ping -n 1 192.168.1.255**. Вы отправляете эхо-запрос на широковещательный адрес клиентской локальной сети. Команда отправит только один эхо-запрос, а не обычные четыре; на него ответит каждое устройство сети.

3.  Закройте окно **MultiServer**.

**Шаг 2. Сгенерируйте веб-трафик (HTTP).**

1.  Нажмите **«Симуляция»** вверху страницы. Под схемой откроется панель «Симуляция», время в сети остановится.

2.  Нажмите на **HTTP-Client** на схеме: откроется окно устройства. На «Рабочем столе» выберите «Веб-браузер».

3.  Введите в адресной строке **192.168.1.254** и нажмите **«Перейти»**. На схеме появится конверт (PDU), а в списке событий на панели «Симуляция» — первое событие.

4.  Закройте окно **HTTP-Client**.

**Шаг 3. Сгенерируйте DNS-трафик.**

1.  Нажмите на **DNS-Client** на схеме: откроется окно устройства. На «Рабочем столе» выберите «Командная строка» (приглашение `C:\>`).

2.  Введите команду **nslookup multiserver.nsalab.local**. На схеме появится еще один PDU.

3.  Закройте окно **DNS-Client**.

**Шаг 4. Убедитесь, что трафик сгенерирован и готов для моделирования.**

Теперь в списке событий на панели «Симуляция» должны быть записи PDU для клиентов HTTP-Client и DNS-Client.

**Шаг 5. Изучите процесс мультиплексирования при передаче трафика по сети.**

Теперь вы будете использовать кнопку **«Шаг»** на панели «Симуляция», чтобы наблюдать за протоколами, перемещающимися по сети. Каждое нажатие выполняет следующее событие.

1.  Нажмите **«Шаг»** два раза. PDU обоих клиентов передаются на коммутатор.

2.  Нажмите **«Шаг»** еще шесть раз и наблюдайте за PDU с разных узлов, пока они перемещаются по сети. Обратите внимание, что в любой момент времени по кабелю в каждом направлении передается только одна PDU.

### Часть 2. Изучение функциональных возможностей протоколов TCP и UDP

**Шаг 1. Изучите HTTP-трафик, когда клиенты обмениваются данными с сервером.**

1.  Нажмите **«Сбросить ↺»** на панели «Симуляция»: список событий очистится, трафик в пути будет удален.

2.  Отфильтруйте отображаемый трафик, чтобы в списке остались только PDU протоколов **HTTP** и **TCP**:

    2.  Отметьте протоколы **HTTP** и **TCP** и закройте окно. Теперь в списке событий будут показаны только PDU трафика **HTTP** и **TCP**.

3.  Нажмите на **HTTP-Client** на схеме и на «Рабочем столе» выберите «Веб-браузер». Введите **192.168.1.254** в адресной строке и нажмите **«Перейти»**, чтобы подключиться к серверу по протоколу HTTP. Закройте окно HTTP-Client.

4.  Нажимайте **«Шаг»**, пока не появится PDU протокола HTTP. Обратите внимание, что цвет конверта на схеме совпадает с цветом квадрата типа HTTP в списке событий.

6.  Посмотрите на значение поля **«Флаги»** в разделе TCP. В нем названы TCP-флаги, установленные для данного этапа обмена данными. Каждый флаг занимает в заголовке TCP один бит, и за один раз можно установить несколько флагов: тогда их имена перечисляются через дефис, например **SYN-ACK** или **PSH-ACK**. Назначение флагов показано ниже.

    | Флаг | Назначение |
    |------|------------|
    | URG  | в сегменте есть срочные данные |

    | PSH  | данные нужно сразу передать приложению |
    | RST  | сброс соединения |
    | SYN  | синхронизация номеров последовательности (установление соединения) |
