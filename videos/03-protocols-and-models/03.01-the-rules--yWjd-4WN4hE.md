## Цель для обучающегося

Обучающийся должен понять ключевую идею модуля: устройство «не видит» сеть — оно знает только собственные адреса (MAC, IPv4/IPv6, шлюз, DNS), а всё остальное (в какой я сети? назначение рядом или за маршрутизатором? куда отправить? дошло ли? повторить?) решают **протоколы** — согласованные правила, причём на каждый вопрос есть свой протокол. Это мотивация к понятиям «протокол», «набор протоколов» и моделям уровней, которые идут дальше в модуле.

Текст 3.1.2–3.1.4 вводит три элемента коммуникации (источник, получатель, канал), требования протокола и правила — абстрактно, через аналогию с человеческим общением. Видео добавляет конкретику сети: (1) схему с реальными адресами и карточку устройства (Ethernet MAC, WLAN MAC, IPv4/IPv6, шлюзы, DNS); (2) пять вопросов «пузыря»; (3) привязку вопросов к протоколам: Ethernet/WLAN — физическое подключение, DHCP/ICMPv6 — адресация, DNS — имя → адрес, IP — доставка, TCP — надёжность; (4) длинный список протоколов, которые встретятся в курсе. Адреса и термины диктор просит пока не запоминать.

## Предложение по пересборке

**Формат:** `анимация Figma (≤ 60 с)` без голоса как иллюстрация к 3.1.1 (пузырь → вопросы → стрелки протоколов) **или** `видео с генерированным голосом (код-рендер)` ~2:00 с тем же сценарием. Контент — чистая метафора на одной схеме; CLI нет, симулятору ничего не требуется.

Сцены для генератора:

1. **Топология** → 2 коммутатора, 5 ПК с IPv4/IPv6-подписями, маршрутизатор `192.168.1.1 / fe80::1`, облако, DNS `8.8.8.8` → «Так видим сеть мы.»
2. **Карточка устройства** → MAC Ethernet/WLAN, IPv4/IPv6, шлюзы, DNS → «Устройство знает только это.»
3. **Пузырь** → ПК в пузыре, остальная схема гаснет → «А сеть оно не видит.»
4. **Пять вопросов** → по одному: какая у меня сеть? получатель рядом или нет? куда слать дальше? дошло? повторить? → «На эти вопросы устройство само ответить не может.»
5. **Протоколы** → по стрелке: Ethernet/WLAN (линия), DHCP/ICMPv6 (адреса, шлюз, DNS), DNS (`www.example.com` → адрес), IP (доставка), TCP (надёжность, повтор) → «На каждый вопрос — свой протокол.»
6. **Список** → карточка протоколов курса → «Все они — впереди.»

Ассеты: топология (2 коммутатора, 5 ПК, маршрутизатор, облако, DNS-сервер); карточка адресов; пузырь; четыре цветные стрелки протоколов; карточка-список.

**Замечания к оригиналу:** фактических ошибок нет. На слайде DNS-сервер подписан `2001:4840:4860::8888`, а в карточке устройства — `2001:4860:4860::8888` (правильный Google DNS — второй); при пересборке унифицировать или заменить на документационный адрес. В тексте курса эта идея не повторяется — видео стоит сохранить в какой-либо форме.
