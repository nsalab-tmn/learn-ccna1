## Цель для обучающегося

Обучающийся должен уметь прочитать таблицу маршрутизации IPv4: что такое источник маршрута (буквы `C`, `L`, `O`, `S*`), что в записи `O 10.1.1.0/24 [110/65] via 209.165.200.226, 00:39:32, Serial0/1/0` значат административная дистанция, метрика, next hop, время с последнего обновления и исходящий интерфейс; что `L` — адрес самого интерфейса (/32) под каждой `C`-записью; что строки без буквы — заголовки (родительские сети); и зачем нужен маршрут по умолчанию `S* 0.0.0.0/0`.

Текст 8.5.6 даёт листинг `show ip route` R1 (другая топология: R1 ↔ R2 через G0/0/1, OSPF-маршрут 10.1.1.0 с `[110/2]`, `S* 0.0.0.0/0 [1/0] via 209.165.200.226`) и список кодов. Видео добавляет: (1) топологию с пятью сетями и понятием «напрямую подключённая» vs «удалённая» сеть; (2) как попасть в CLI и выполнить `show ip route`; (3) разбор `[110/65]` как AD/метрика; (4) смысл таймера `00:39:32` и исходящего интерфейса `Serial0/1/0`; (5) вариант маршрута по умолчанию через исходящий интерфейс (`is directly connected, Serial0/1/0`) вместо next hop — полезно показать оба.

## Сценарий

Топология PT (окно `Cisco Packet Tracer – …\CCNAv7 Authoring\Final PT Files\IPv4 Routing Table.pkt`): **PC1** — **S1** — **R1** `G0/0/0` (подпись `Net: 192.168.1.0/24`); **PC2** — **S2** — **R1** `G0/0/1` (`Net: 192.168.2.0/24`); **R1** `S0/1/0` — красная serial-линия — `S0/1/1` **R2** (`Net: 209.165.200.224/30`); **R2** `G0/0/0` — **S3** — **PC3** (`Net: 10.1.1.0/24`); **R2** `G0/0/1` — **S4** — **PC4** (`Net: 10.1.2.0/24`). Все линки зелёные.

## Предложение по пересборке

**Формат:** `видео с генерированным голосом (код-рендер)` ~3:00 — топология (с подсветкой сетей) + рендер терминала с построчной подсветкой и всплывающими подписями частей записи (`O | 10.1.1.0/24 | [110/65] | via 209.165.200.226 | 00:39:32 | Serial0/1/0`). Согласовать с текстом 8.5.6: либо перерисовать листинг в тексте под топологию видео, либо в видео использовать топологию текста (R1 ↔ R2 по G0/0/1, `[110/2]`, `S* … [1/0] via 209.165.200.226`). Для симулятора — сессия ниже; это базовый сценарий «прочитай таблицу» (и заготовка для 10.x/11.x: тот же PKT с OSPF и статическим маршрутом).

Сцены для генератора:

1. **Топология** → 5 сетей, подсветка трёх connected у R1 и двух remote → «Три подключённые, две удалённые — о них R1 узнал по OSPF.»
2. **show ip route** → `enable`, `show ip route`; блок кодов с подсветкой L / C / S / O → «Буква — откуда маршрут.»
3. **Запись C и L** → `C 192.168.1.0/24 … GigabitEthernet0/0/0`, `L 192.168.1.1/32 …` → «C — сеть на интерфейсе; L — адрес самого интерфейса.»
4. **Запись O** → разбор по частям: `[110/65]` → AD 110 (OSPF), метрика 65 (стоимость serial 64 + GigE 1); `via 209.165.200.226` (S0/1/1 R2); `00:39:32`; `Serial0/1/0` → по фразе на часть.
5. **Заголовки** → `10.0.0.0/24 is subnetted, 2 subnets` и `… is variably subnetted, 2 subnets, 2 masks` → «Строки без буквы — группировка, не маршруты.»
6. **S\*** → `Gateway of last resort is 0.0.0.0 to network 0.0.0.0`, `S* 0.0.0.0/0 is directly connected, Serial0/1/0` → «Маршрут по умолчанию — чтобы ничего не отбрасывать.»
7. **Карточка** → анатомия записи таблицы → итог.

Ассеты: топология (2 маршрутизатора ISR 4321/4331, 4 коммутатора, 4 ПК, serial-линк); рендер терминала; карточка «анатомия записи».

Подразумеваемая конфигурация (для воспроизведения в тренажёре): R1 — `G0/0/0 192.168.1.1/24`, `G0/0/1 192.168.2.1/24`, `S0/1/0 209.165.200.225/30`, `ip route 0.0.0.0 0.0.0.0 Serial0/1/0`, `router ospf 1` с сетями R1; R2 — `S0/1/1 209.165.200.226/30`, `G0/0/0 10.1.1.1/24`, `G0/0/1 10.1.2.1/24`, OSPF. Метрика 65 = стоимость serial (1544 кбит/с → 64) + GigabitEthernet (1).

**Замечания к оригиналу:** (1) расхождение с текстом 8.5.6 (другая топология и листинг: `[110/2]`, `S* 0.0.0.0/0 [1/0] via 209.165.200.226`) — при пересборке привести к одному варианту или показать оба вида маршрута по умолчанию (через next hop и через интерфейс); (2) «строки без буквы — просто заголовки» — упрощение; это родительские (классовые) сети, их структура разбирается в CCNA2; (3) голос называет «отметку времени» — точнее «время с момента последнего обновления маршрута»; (4) авто-субтитры: «show iprout» = `show ip route`, «lands» = LANs; (5) фактических ошибок нет; AD 110 и метрика 65 верны для OSPF через serial 1544 кбит/с.
