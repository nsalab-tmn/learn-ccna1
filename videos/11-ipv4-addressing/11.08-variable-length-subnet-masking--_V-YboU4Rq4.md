## Цель для обучающегося

Уметь решить типовую задачу VLSM: из **172.16.0.0/23** (512 адресов, магическое число 2 в третьем октете → следующая сеть 172.16.2.0/23) нарезать подсети под требования 200, 100, 50, 25, 10 хостов и 4 канала точка-точка по 2 хоста. Метод: (1) округлить каждое требование вверх до степени двойки с учётом двух служебных адресов: 200 → 256, 100 → 128, 50 → 64, 25 → 32, 10 → 16, 2 → 4 (×4); (2) проверить, что сумма 256 + 128 + 64 + 32 + 16 + 16 = 512 помещается в блок; (3) идти от большей к меньшей, каждый раз деля **вторую половину** оставшегося блока пополам: /23 → /24 (0.0 — оставить, 1.0 — делить) → /25 (1.0 — оставить, 1.128 — делить) → /26 (1.128 — оставить, 1.192 — делить) → /27 (1.192 — оставить, 1.224 — делить) → /28 (1.224 — оставить, 1.240 — делить) → четыре /30 (1.240, 1.244, 1.248, 1.252); (4) проверить отсутствие перекрытий по диапазонам (0.0–0.255, 1.0–1.127, 1.128–1.191, 1.192–1.223, 1.224–1.239, 1.240–1.243 …). Итог — девять подсетей.

Текст темы 11.8.3–11.8.5 показывает VLSM на другом примере (192.168.20.0/24: четыре LAN /27 + три WAN /30 из .224/27) и даёт таблицу назначения адресов. Видео добавляет общий **алгоритм** (округление требований, проверка суммы, деление «второй половины», проверка перекрытий) на более богатом примере с шестью разными размерами. Это ядро темы 11.8 — ролик нужно сохранить в пересборке.

**Замечания о точности оригинала:**

1. Фактических ошибок нет; все адреса и размеры верны (256 + 128 + 64 + 32 + 16 + 4 × 4 = 512).
2. Диктор чередует «hosts» и «addresses» (на 1:28 говорит «512 hosts», затем сам оговаривает, что это адреса). В пересборке строго: «адресов» для размера блока, «хостов» для 2ⁿ − 2.
3. Метод «делим вторую половину» даёт упорядоченное дерево, но не объясняется, что первую половину можно было бы делить так же — выбор произвольный; стоит сказать.
4. Не показан вывод, что сумма ровно 512 означает отсутствие резерва; в тексте 11.8.4 отмечается, что VLSM оставляет подсети для будущего роста — в пересборке полезно привести вариант с запасом.
5. Для задач из 11.8.5 (адреса интерфейсов) ролик не доходит до назначения адресов хостам/шлюзам — можно добавить финальную сцену с таблицей «подсеть → диапазон хостов → широковещательный».

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер), ~3:30 — дерево подсетей строится автоматически, синхронно с голосом; с прологом из R_Ti9y2AShc (≤ 30 с) получится один ролик «VLSM» ~4:00.

**Ассеты:** панель требований с колонкой «→ блок» (200 → 256 …); «линейка» 512 адресов 172.16.0.0–172.16.1.255, которая режется пополам на каждом шаге (левая половина фиксируется с подписью, правая делится дальше); дерево подсетей (как на слайде) с зачёркиванием; итоговая таблица «подсеть / маска / адресов / хостов / диапазон / broadcast».
