## Цель для обучающегося

Научиться быстро перечислять подсети без двоичной арифметики: (1) заимствование s битов из хостовой части /24 даёт 2ˢ подсетей и 2ʰ − 2 хостов (таблица /25 → 2×126, /26 → 4×62, /27 → 8×30, /28 → 16×14, /29 → 32×6, /30 → 64×2); (2) **магическое число** — позиционный вес (place value) последней единицы маски в октете, где заимствуются биты (/25 → 128, /26 → 64, /27 → 32, /28 → 16, /29 → 8, /30 → 4); (3) адреса подсетей идут с шагом, равным магическому числу, начиная с 0, и не превышают 256 − шаг; (4) приём работает в любом октете — для 172.16.0.0/16 → /23 магическое число 2 в третьем октете: 172.16.0.0, 172.16.2.0, 172.16.4.0 … по 510 хостов (диапазон 172.16.0.1–172.16.1.254, широковещательный 172.16.1.255).

Текст темы 11.5.2 даёт таблицу «/25…/30 → число подсетей/хостов» и текст 11.6 — разбиение /16 и /8. Видео добавляет сам **метод** перечисления подсетей (магическое число = вес последней единицы маски), наглядную таблицу весов 2⁷…2⁰ с подсветкой последней единицы, полные списки подсетей для каждой маски и перенос приёма в третий октет (11.6). Это основной практический навык для всех лабораторных по адресации; его стоит сохранить как отдельный короткий ролик.

**Замечания о точности оригинала:**

1. Фактических ошибок нет; оговорки диктора: «with three bits we now have a slash 25, 26, 27» (сам поправляется), «2 to the 4th power of hosts per network so there's 16 or 14 usable» (имеется в виду 16 адресов, 14 хостов), «192.168.1.0.27» вместо «/27».
2. Порядок сцен скачет: /30 показан на 4:04, затем /29 на 4:49 (автор листает назад); списки /29 и /30 на этих слайдах напечатаны очень мелко — в пересборке дать таблицей.
3. «Класс A/B/C» — историческая терминология; в пересборке говорить «сеть /16» и «сеть /8».
4. Не сказано, что приём равносилен формуле «шаг = 256 − последний ненулевой октет маски» (256 − 224 = 32) — полезное дополнение для тех, кто не хочет считать веса битов.
