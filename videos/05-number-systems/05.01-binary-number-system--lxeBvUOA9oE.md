## Цель для обучающегося

Обучающийся должен уметь, пользуясь таблицей весов разрядов 128-64-32-16-8-4-2-1, переводить восьмибитный октет в десятичное число (сложить веса позиций с единицами) и десятичное число 0–255 в восемь бит (идти слева направо, спрашивая «помещается ли вес?»), а затем применить это к четырём октетам IPv4-адреса.

Текст 5.1.3–5.1.7 даёт те же таблицы (десятичная и двоичная позиционные системы, таблица весов, примеры 192.168.10.10, перевод в обе стороны). Видео добавляет: (1) мотивацию через знакомую десятичную систему (2168 = 2·1000 + 1·100 + 6·10 + 8·1 и 10⁰…10⁶); (2) проговорённый алгоритм «нужен ли мне 128? … 64 даст 192 — перебор»; (3) обратный пример 01101101 → 109; (4) полный адрес по октетам. По сути видео — проговорённая версия текста; новых фактов нет, но есть ритм вычисления, который полезно сохранить в анимации.

## Предложение по пересборке

**Формат:** `анимация Figma (≤ 60 с)` ×2 (десятичное → двоичное на 168; двоичное → десятичное на целом адресе) как интерактивно-выглядящие иллюстрации к 5.1.5/5.1.7, **либо** `видео с генерированным голосом (код-рендер)` ~3:00 (оригинал растянут повторами). Десятичную «разминку» (2168, 10⁰…10⁶) сократить до одной сцены — текст 5.1.3 её уже даёт. Симулятору ничего не требуется; но тот же сценарий — готовый шаблон тренажёра «перевод октета» с пошаговыми подсказками «помещается ли 128?».

Сцены для генератора:

1. **Десятичная** → таблица `10³ 10² 10¹ 10⁰` / `1000 100 10 1` / `2 1 6 8`, расчёт 2000+100+60+8 → «Вес разряда — степень основания; в десятичной — десять символов.»
2. **Двоичная таблица** → `2⁷…2⁰` / `128 64 32 16 8 4 2 1`, пустая строка → «Два символа, веса — степени двойки; восемь бит — байт.»
3. **168 → биты** → по разрядам слева направо: 128 ✓ (1, остаток 40), 64 ✗ (0), 32 ✓ (1, остаток 8), 16 ✗, 8 ✓ (остаток 0), 4 2 1 → 0 → «Помещается — единица и вычитаем; нет — ноль.» Итог `10101000`.
4. **01101101 → 109** → биты в таблицу, подсветка весов 64+32+8+4+1 → «Складываем веса под единицами.»
5. **Адрес** → полоса из четырёх октетов; каждый прогоняется через таблицу: 192, 168, 1, 101 → «Октет за октетом — 192.168.1.101.»

Ассеты: таблица весов с анимируемыми ячейками; полоса из 4 октетов с результатами; стрелка-курсор «вопрос к разряду».

**Замечания к оригиналу:** (1) опечатка на титуле «Convert an P address»; (2) на слайде 2:28 при замене 2 → 9 строка `Total` остаётся `2168` (должно быть 9168); (3) в заголовках части слайдов «Binary – Base 2 (0,1,)» — лишняя запятая; (4) алгоритм «нужен ли вес?» в видео опирается на устный подсчёт сумм (128+32=160…), а текст 5.1.5 — на вычитание остатка; при пересборке показать остаток явно (168 − 128 = 40, 40 − 32 = 8, 8 − 8 = 0) — это универсальнее. Фактических ошибок в вычислениях нет.
