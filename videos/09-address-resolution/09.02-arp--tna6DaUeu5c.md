## Цель для обучающегося

Увидеть по шагам, что делает хост, когда у него есть IPv4-пакет для узла в своей же сети, но нет MAC-адреса назначения: проверка ARP-кеша → пакет «на удержании» (on hold) → ARP-запрос с известным Target IPv4 и неизвестным Target MAC → широковещательный кадр (destination MAC FF-FF-FF-FF-FF-FF) → коммутатор рассылает его во все порты, кроме входящего → каждый узел (PC-B, R1) сравнивает Target IPv4 со своим и молчит, роутер не пересылает запрос дальше → только PC-C узнаёт себя и будет отвечать.

Текст темы 9.2.3 уже описывает содержимое заголовка Ethernet ARP-запроса (FF-FF…, source MAC, Type 0x806), широковещательную рассылку через коммутатор и то, что роутер не пересылает broadcast. Видео добавляет: (а) конкретную топологию с адресами и сокращёнными MAC, на которой можно проследить путь кадра; (б) визуальную связку «пакет на удержании — ARP-запрос — ответ»; (в) явное сравнение Target IPv4 на каждом получателе («The target IPv4 is not me» / «The target IPv4 is me!»), которого в тексте нет как последовательности. Видео 9.2.4 (Ud1angOlxHE) продолжает тот же сюжет ARP-ответом — пересобирать их логично как одну анимацию или пару.

## Сценарий

Видео — один слайд-схема Cisco, элементы появляются поочерёдно. Топология на все сцены: коммутатор в центре; слева **PC-A 192.168.1.110, MAC 00-0A**; сверху **PC-B 192.168.1.120, MAC 00-0B**; справа **PC-C 192.168.1.50, MAC 00-0C**; снизу **роутер R1 192.168.1.1, MAC 00-0D**, от R1 красная «молния» к облаку «Internet». Внизу — полоска кадра: красные ячейки «Ethernet Header» (Destination MAC / Source MAC) и синие ячейки полезной нагрузки. Слева вверху появляется таблица «PC-A's ARP Cache» (колонки IPv4 Address / MAC Address, пустая). Речь — один мужской голос.

**Замечания о точности оригинала (учесть при пересборке):**

1. Диктор и ручные субтитры называют адрес PC-A «192.168.1.**10**», тогда как на схеме и в полоске пакета — «192.168.1.**110**». В пересборке использовать .110 (тогда адреса PC-A/PC-B/.1 совпадают с таблицей `arp -a` в тексте 9.2.7, где есть 192.168.1.110).
2. На схеме поле Type (0x806) кадра не показано, хотя текст 9.2.3 его описывает — в пересборке добавить ячейку «Type 0x806» между Source MAC и полезной нагрузкой.
3. В ARP-запросе показаны только Target IPv4/Target MAC; реальный запрос также несёт Sender IPv4/Sender MAC (их и кладёт в кеш получатель). Для цели курса (ITN) допустимо упростить, но стоит хотя бы упомянуть голосом.

## Транскрипт

Ручные субтитры (en), свод по 20 с:

```
[0:03] In this video we're going to see PC A send an ARP request for the MAC address of PC C. PC A has an IP packet with the source IP address of itself 192.168.1.10 and the destination IP address of PC C at 192.168.1.50.
[0:26] So it needs to know what the destination mac address will be. Because the source and destination IP addresses are on the same network, the destination MAC address will be that of the destination IP address of PC C at 192 168 1.50. So PC A checks its ARP cache for the IP address 192 168 1.50. Because it is not in its ARP cache,
[0:56] it will put the packet on hold and create an ARP request. The ARP request contains the target IPv4 address, this is the IPv4 address which is known by PC A and the target MAC address which is unknown. This is what PC A is wanting to find out. The ARP request is sent as a broadcast,
[1:20] so everybody on the network will need to examine this ethernet frame and process the ARP request. So PC A sends it to the switch, because it is a broadcast the switch will flood it out all ports, except for the port that it came in on. PC B receives the broadcast so it must process it
[1:43] and its ARP process examines the ARP request. it compares its own IPv4 address against the target IPv4 address and notices that they are not the same, so it doesn't need to send an ARP reply. The router R1 also receives this ARP request. It's our process examines its own IPv4 address
[2:09] and compares that against the target IPv4 address and also realizes this is not its IPv4 address so it does not need to send the ARP reply. By the way routers will not forward ARP requests out other ports. PC C receives the ARP request, compares its IPv4 address
[2:31] against the target IPv4 address, and notices that it is the intended target of the ARP request, that the target IPv4 address does match its own IPv4 address. So PC C will need to send an ARP reply.
```
