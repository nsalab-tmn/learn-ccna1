## Цель для обучающегося

Научиться определять состав и имена интерфейсов любого роутера командой `show ip interface brief` (и понимать, что идентификаторы интерфейсов зависят от модели и установленных карт расширения: `GigabitEthernet0/0/0` на ISR 4000 против `GigabitEthernet0/0` на 1900/2900; `Serial0/1/0` против `Serial0/0/0`), различать медное и оптическое подключение по строке `media type is RJ45 / SX` в `show interfaces`, выполнять базовую настройку интерфейса (`configure terminal` → `interface …` → `ip address … …` → `no shutdown`), читать системные сообщения `%LINK-3-UPDOWN` / `%LINEPROTO-5-UPDOWN` и проверять связность `ping`, в том числе объяснять потерю первого эхо-запроса (ARP).

Текст темы 10.3 (шлюз по умолчанию) и соседних 10.1–10.2 уже даёт синтаксис настройки интерфейсов и `show ip interface brief` на примере R1/R2 с G0/0/0, G0/0/1. Видео добавляет: три разных модели бок о бок с реальным выводом (включая строки `Embedded-Service-Engine0/0` и `GigabitEthernet0` — управляющие интерфейсы, которые озадачивают новичков), полный вывод `show interfaces` c полями `media type`, `BW`, `Full Duplex`, счётчиками, реальную последовательность сообщений при `no shutdown` (сначала `changed state to down`, затем `up`, когда поднялась другая сторона), и показательный `ping` с 80 % → 100 %. Для нашего симулятора это эталонный сценарий «тур по интерфейсам + первая адресация точка-точка».

Видео — экранная запись терминальных вкладок («4000 Series» белый фон, «2900 Series» фиолетовый фон, «1900 Series» синий фон) с окном 80×24; во врезке справа — топология. Имена устройств в промптах: `R1_4000`, `R2_2900`, `R3_1900`. Речь — один мужской голос, разговорный стиль.

**Замечания о точности оригинала (учесть при пересборке):**

1. Диктор называет интерфейсы «gig zero zero zero» и т. п.; в терминале всегда полная форма `gigabitEthernet 0/0/0` через Tab-дополнение — в пересборке показывать и полную, и сокращённую (`g0/0/0`) формы.
2. `GigabitEthernet0` на 4321 (выделенный management-порт, VRF Mgmt-intf) и `Embedded-Service-Engine0/0` на 2951/1941 — не объяснены. В пересборке сказать одной фразой: «служебные интерфейсы, в лабораторных не используются».
3. На R1 после `no shutdown` сообщения о подъёме линка не показаны (линк поднялся только когда настроили R2 — видно по `%LINK-3-UPDOWN … up` на R2 и успешному ping). На R2 g0/2 показано только `changed state to down` — это нормальная реакция на `no shutdown` при выключенном соседе; стоит озвучить явно, иначе учащийся сочтёт это ошибкой.
4. Диктор говорит «ping 172.16.0» (адрес 172.16.0.1 полностью виден в терминале) и «1001» вместо 10.0.0.1.
5. На R1 команда `config t` в первой сцене набрана как `confi` + перебита syslog-сообщением — поэтому автор сразу включает `logging synchronous` на `line con 0`; в пересборке это хороший повод показать команду.
6. Канал R1 G0/0/1 ↔ PC1 показан как 100 Мбит/с (`BW 100000 Kbit/sec`, `100Mbps`) — PC1 договорился на 100 Мбит; не ошибка, но в симуляторе проще показать 1000.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер терминала), ~4:00; плюс **текст + иллюстрация** «три роутера — три схемы имён интерфейсов» (таблица). Физические модели в пересборке не нужны: три устройства симулятора с разными «профилями» интерфейсов (A: `G0/0/0, G0/0/1, S0/1/0, S0/1/1`; B: `G0/0, G0/1, G0/2, S0/0/0, S0/0/1, S0/1/0, S0/1/1`; C: `G0/0, G0/1, S0/0/0, S0/0/1`).

**Ассеты:** топология (три роутера R1/R2/R3, PC1, PC2, подписи интерфейсов, оранжевая линия для оптики, «молния» для serial), три терминальных окна с разным цветом фона, подсветка строк вывода, таблица «модель → схема имён».
