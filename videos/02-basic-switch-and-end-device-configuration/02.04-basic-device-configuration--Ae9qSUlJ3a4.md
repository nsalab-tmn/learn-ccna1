## Цель для обучающегося

Обучающийся должен уметь закрыть все три «двери» в коммутатор — консоль (`line console 0` → `password` + `login`), привилегированный режим (`enable secret`) и виртуальные линии (`line vty 0 15` → `password` + `login`), — зашифровать пароли в конфигурации (`service password-encryption`), поставить юридическое предупреждение (`banner motd`) и убедиться в результате: в `show running-config` увидеть `enable secret 5 …` и `password 7 …`, а при новом входе — баннер и два запроса пароля.

Текст 2.4.1–2.4.5 даёт каждую команду отдельным фрагментом на устройстве Sw-Floor-1. Видео собирает их в одну непрерывную сессию и добавляет то, чего в тексте нет: (1) исходную уязвимость — вход без пароля и `enable` без пароля; (2) проверку после каждого шага выходом (`exit`) и повторным входом — `User Access Verification / Password:`; (3) как `show running-config` показывает `enable secret 5 $1$mERr$…` (хеш) рядом с `password cisco` открытым текстом; (4) что IOS сам разбивает `line vty 0 15` на `line vty 0 4` и `line vty 5 15`; (5) вид тех же паролей после шифрования — `password 7 0822455D0A16`; (6) что баннер показывается *до* запроса пароля. Команды `hostname` в видео нет (имя Switch1 уже задано).

## Предложение по пересборке

**Формат:** `видео с генерированным голосом (код-рендер)` ~3:30 — терминал + сбоку схема «три двери» (console / enable / vty) с замками, которые закрываются по мере настройки; вывод `show running-config` показывать с пропусками (`…`) и подсветкой нужных строк. Для симулятора — сессия ниже; это основной тренинг темы 2.4 (можно начать с `hostname Switch1`, чтобы покрыть 2.4.1).

Сцены для генератора:

1. **Без защиты** → Enter → `Switch1>` → `enable` → `Switch1#`; схема: три открытые двери → «Никакого пароля — любой с консолью получает полный доступ.»
2. **Консоль** → `config t`, `line console 0`, `password cisco`, `login`; замок на двери console → «Пароль на консольную линию и login, чтобы он спрашивался.»
3. **enable secret** → `exit`, `enable secret class`; замок на enable → «secret — пароль хранится как хеш.»
4. **Проверка 1** → Ctrl+C, `exit`, Enter → `User Access Verification / Password:` → `Switch1>` → `enable` → `Password:` → `Switch1#` → «Два запроса пароля; ввод не отображается.»
5. **show run** → `enable secret 5 $1$mERr$…` и `line con 0 / password cisco / login`; подсветка → «Secret захеширован, а пароль консоли — открытым текстом.»
6. **VTY** → `line vty 0 15`, `password cisco`, `login`; `show run` → `line vty 0 4 … line vty 5 15` → «16 виртуальных линий; IOS показывает их двумя группами.»
7. **Шифрование** → `service password-encryption`; `show run` → `password 7 0822455D0A16` → «Type 7 — слабое, но пароли больше не читаются с экрана.»
8. **Баннер** → `banner motd # Authorized access only! … #` → «Разделитель — любой символ, которого нет в тексте.»
9. **Проверка 2** → `exit`, Enter → баннер → `Password:` → `enable` → `Password:` → `Switch1#`; все три замка закрыты → «Баннер показывается до пароля.»

Ассеты: рендер терминала; схема «три двери» (console, enable, vty) с замками; подсветка строк конфигурации.

**Замечания к оригиналу:** (1) голос: «secret assures the password will be encrypted» — точнее «захеширован» (MD5, type 5), что диктор сам и говорит минутой позже («hashed»); (2) `service password-encryption` диктор называет «light level of encryption» — верно, type 7 обратим; в тексте 2.4.4 так же; (3) `hostname` не показан — при пересборке добавить первой командой; (4) в первом `show run` линии `vty 0 4 / login` без пароля — диктор не поясняет, что в таком состоянии удалённый вход отвергается с сообщением `Password required, but none set` — полезная фраза для пересборки.
