## Цель для обучающегося

Обучающийся должен понимать разницу между running-config (RAM, теряется) и startup-config (NVRAM, сохраняется), уметь сохранять (`copy running-config startup-config` / `copy run start`), проверять наличие файла (`dir nvram:`), сбрасывать устройство к заводскому состоянию (`erase startup-config` + `reload`) и откатывать несохранённые изменения загрузкой startup-config в running-config (`copy startup-config running-config`), помня, что это **слияние**, а не замена.

Текст 2.5.1–2.5.2 даёт команды `show running-config`, `show startup-config`, `copy running-config startup-config`, `reload` (с ответом `n` на вопрос о сохранении) и `erase startup-config`. Видео добавляет: (1) диалог `Destination filename [startup-config]?` и ответ Enter; (2) `dir ?` → `flash:` / `nvram:` и `dir nvram:` с файлом `startup-config` (1205 байт); (3) сокращение `copy run start`; (4) наглядную проверку сохранения через `reload` (имя узла и баннер остались); (5) сообщения `erase startup-config`: `Erasing the nvram filesystem will remove all configuration files! Continue? [confirm]` → `[OK]` / `Erase of nvram: complete` / `%SYS-7-NV_BLOCK_INIT`; (6) `copy startup-config running-config` как откат — его в тексте нет вовсе — с оговоркой про слияние.

## Сценарий

Только окно CLI коммутатора 2960 («IOS Command Line Interface», кнопка Copy). Начальное состояние: сохранённая конфигурация с баннером `No unauthorized access allowed violators will be prosecuted to the extent of the law!`, паролем консоли `cisco`, enable-паролем `class`, именем `Switch`.

## Предложение по пересборке

**Формат:** `видео с генерированным голосом (код-рендер)` ~3:30 — терминал + сбоку схема двух «ящиков» RAM (running-config) и NVRAM (startup-config) со стрелками `copy run start` / `copy start run` / `reload` / `erase`, содержимое которых меняется синхронно с командами. Вывод загрузки при `reload` сжать до 3 секунд. Для симулятора — сессия ниже; добавить в конец проверку слияния (см. замечания).

Сцены для генератора:

1. **Два ящика** → RAM «running-config» и NVRAM «startup-config»; подпись «RAM стирается при выключении» → «Текущая конфигурация живёт в RAM, сохранённая — в NVRAM.»
2. **hostname S1 → copy run start** → терминал; стрелка RAM→NVRAM; `Destination filename [startup-config]?` Enter → «Enter принимает имя по умолчанию.»
3. **dir nvram:** → строка `startup-config 1205` → «Файл действительно лежит в NVRAM.»
4. **copy run start** → «Сокращение: copy run start.»
5. **reload** → короткий boot → баннер, пароль, `S1>` → «Всё на месте — конфигурация сохранена.»
6. **erase startup-config** → предупреждение, `[OK]`, `Erase of nvram: complete`; ящик NVRAM пустеет → `reload` → `Switch>` без баннера → «Завод.»
7. **MySwitch → copy run start → ещё изменения → hostname S1** → ящики: NVRAM = MySwitch; RAM = S1 + line con 0 → «Сохранили MySwitch, потом наделали лишнего.»
8. **copy start run** → стрелка NVRAM→RAM, `1045 bytes copied…`, приглашение `MySwitch#` → «Откат — но это слияние: пароль консоли из RAM никуда не делся.» (показать `show running-config | section line con`)

Ассеты: рендер терминала; схема RAM/NVRAM с анимируемым содержимым.

**Замечания к оригиналу:** (1) утверждение о слиянии верно, но не показано: после `copy start run` в running-config остаются `line con 0 / password cisco / login`, хотя в startup-config их нет — при пересборке добавить `show running-config` (или `show run | section line con`) и фразу «откатить добавленные команды так нельзя — только `no …` или reload без сохранения»; (2) `reload` после `erase startup-config` в PT не спрашивает «System configuration has been modified. Save?» — на реальном IOS спросит, и ответ должен быть `no` (это есть в тексте 2.5.2, стоит проговорить); (3) в первой части reload и второй — MAC `0000.0CE9.C632` (коммутатор в этом ролике — другой экземпляр, чем в 2.4.6 с `00D0.D36C.A77B`), не важно; (4) хеш-строки `copy run start` → `[OK]`: на реальном IOS между ними печатается `Building configuration...` так же — всё совпадает.
