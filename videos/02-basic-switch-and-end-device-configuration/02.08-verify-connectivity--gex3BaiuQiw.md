## Цель для обучающегося

Обучающийся должен уметь проверять связность командой `ping` с ПК до коммутаторов (SVI) и до другого ПК, читать вывод (`Reply from … bytes=32 time<1ms TTL=…`, `Request timed out.`, статистика `Sent / Received / Lost`), не пугаться одного потерянного первого эха при первом обращении (ARP) и всегда проверять связность в обратную сторону, потому что односторонний результат обычно указывает на брандмауэр хоста (Windows Firewall по умолчанию блокирует ICMP echo request).

Текст 2.8.2 — две фразы о `ping`. Видео добавляет: (1) где в PT запускается `ping` (PC → Desktop → Command Prompt); (2) точный вывод `ping` в PT и разницу TTL=255 (ответ коммутатора) / TTL=128 (ответ Windows-ПК); (3) объяснение «первый запрос тайм-аут, остальные три — ответ» (причину диктор оставляет за кадром — это ARP-разрешение); (4) правило «проверяй в обе стороны» и его причину.

## Предложение по пересборке

**Формат:** `видео с генерированным голосом (код-рендер)` ~1:45 — рендер Command Prompt с подсветкой `Request timed out.`, `TTL=255`/`TTL=128` и строки статистики; мини-схема с анимированной стрелкой echo request/reply между узлами. Объединить с 2.8.1 в один ролик ≈ 4:00 или оставить отдельным. Для симулятора — сессия ниже (ПК-сторона); первый тайм-аут симулятор должен воспроизводить (ARP) — это учебно важный эффект.

Сцены для генератора:

1. **Схема** → PC-A (.10), S1 (.2), S2 (.3), PC-B (.11) → «Проверим все четыре адреса одной командой — ping.»
2. **ping S1** → `ping 192.168.1.2`: `Request timed out.` + 3 ответа, стрелки на схеме → «Первый пакет потерян — ПК сначала выяснял MAC-адрес (ARP); остальные три дошли.»
3. **Повтор** → ↑, 4/4 → «Повторный ping — без потерь.»
4. **ping S2** → то же для .3 → «Через два коммутатора — то же самое.»
5. **ping PC-B** → 4/4, подсветка `TTL=128` против `TTL=255` → «TTL подсказывает, кто ответил: 255 — IOS, 128 — Windows.»
6. **Обратно** → PC-B: `ping 192.168.1.10` 4/4 → «Проверяйте в обе стороны: если только в одну — обычно брандмауэр хоста блокирует ICMP.»
7. **Карточка** → строки вывода ping и что они значат (`Reply`, `Request timed out.`, `Sent/Received/Lost`) → итог.

Ассеты: рендер Command Prompt; мини-топология с анимацией echo request/reply; карточка.
