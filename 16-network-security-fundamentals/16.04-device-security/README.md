## Безопасность устройства по умолчанию

Сетевые устройства требуют особого внимания для поддержания безопасности. Вероятно, у вас уже есть пароль для компьютера, смартфона или планшета. Является ли он максимально безопасным? Используете ли вы другие инструменты для повышения безопасности своих устройств? В этом разделе рассказывается, как это сделать.

Система безопасности на устройстве настроена по умолчанию при установке новой операционной системы. В большинстве случаев этот уровень безопасности является недостаточным. На некоторых маршрутизаторах базовые защитные настройки можно применить одной командой: команда **auto secure** в диалоге отключает ненужные службы и включает основные механизмы защиты, как показано в примере.

```
Router#auto secure
                      --- AutoSecure Configuration ---

*** AutoSecure configuration enhances the security of
the router, but it will not make it absolutely resistant
to all security attacks ***

AutoSecure will modify the configuration of your device.
All configuration changes will be shown. For a detailed
explanation of how the configuration changes enhance security
and any possible side effects, please refer to the
Autosecure documentation.
At any prompt you may enter '?' for help.
Use ctrl-c to abort this session at any prompt.

Gathering information about the router for AutoSecure

Is this router connected to internet? [no]:
```

Когда на все вопросы диалога даны ответы, маршрутизатор показывает сформированную конфигурацию и спрашивает, применить ли ее. Среди прочего она отключает протокол CDP и оба веб-сервера маршрутизатора, HTTP и HTTPS (команды **no ip http server** и **no ip http secure-server**), задает баннер, пароли, ограничение попыток входа и включает SSH, как показано в примере.

```
This is the configuration generated:

service password-encryption
no cdp run
no ip http server
no ip http secure-server
banner motd ^C
Unauthorized access only!
^C
security passwords min-length 6
enable secret 5 $1$mERr$ZBBt6ccfHmu2dCR1
enable password 7 00071A1507545A545C7519
username admin password 7 0005170B0D555A545C7519
line con 0
 exec-timeout 5 0
line vty 0 4
 transport input telnet
login block-for 60 attempts 2 within 30
hostname R1
ip domain-name example.net
crypto key generate rsa general-keys modulus 2048
line vty 0 4
 transport input ssh telnet
end

 Apply this configuration to running-config? [yes]:
```

Кроме того, для большинства операционных систем можно применить простые шаги:

* немедленно изменить установленные по умолчанию имена пользователей и пароли;
* предоставить доступ к системным ресурсам только лицам с соответствующими правами;
* при возможности отключить или удалить все невостребованные службы и приложения.

Зачастую устройства, полученные от производителя, до отгрузки хранились на складе в течение определенного периода, и поэтому на них не установлены актуальные обновления. ПО и систему безопасности перед внедрением важно сначала обновить.

## Пароли

Для защиты сетевых устройств необходимо использовать надежные пароли. Ниже приведены стандартные рекомендации по выбору пароля.

* длина не менее 8 символов (предпочтительно 10 и более символов), чем длиннее пароль, тем он надежнее;
* выбирайте сложные пароли: комбинации букв в верхнем и нижнем регистре, цифр, специальных символов и пробелов (если допускается их использование);
* избегайте паролей на основе: повторений, слов из словаря, последовательностей букв или цифр, имени пользователя, родственников и домашних животных, даты рождения, номера паспорта и других данных, которые легко выяснить;
* допустите в пароле намеренную ошибку (Ivanov = Ivonov = 1vOnov или Security = 5ecur1ty);
* периодически меняйте пароли: если пароль случайно скомпрометирован, у злоумышленников будет мало возможностей его использовать;
* не записывайте пароли на бумаге и не оставляйте их в легко доступных местах (на столе или на мониторе).

В таблицах приведены примеры ненадежных и надежных паролей.

### Ненадежные пароли

| Ненадежный пароль | Почему пароль ненадежный |
| --- | --- |
| secret | Простое словарное слово |
| smith | Девичья фамилия матери |
| toyota | Марка автомобиля |
| bob1967 | Имя и год рождения пользователя |
| Blueleaf23 | Простые слова и цифры |

### Надежные пароли

| Надежный пароль | Почему пароль надежный |
| --- | --- |
| b67n42d39c | Сочетание букв и цифр |
| 12^h u4@1p7 | Сочетание букв и цифр, специальных символов, а также пробела |

ОС маршрутизатора игнорирует начальные пробелы в паролях, но пробелы после первого символа учитывает. Поэтому один из способов создать надежный пароль — использовать пробел и задать фразу, состоящую из нескольких слов. Это называется парольной фразой. Её зачастую проще запомнить, чем обычный пароль. Парольная фраза также длиннее простого пароля и ее сложнее подобрать.

## Расширенная защита пароля

Самые надежные пароли полезны, пока они никому не известны. Обеспечьте сохранность пароля в тайне на маршрутизаторах и коммутаторах:

* зашифруйте все открытые пароли;
* установите минимальную допустимую длину пароля;
* предотвратите атаки с использованием пароля грубой силы;
* отключите доступ к неактивному привилегированному режиму EXEC через определенное время.

Использование команды глобальной конфигурации **service password-encryption** предотвращает несанкционированный доступ для просмотра паролей в виде обычного текста в файле конфигурации. Команда шифрует все открытые пароли. Например, пароль «netlab123» после этой команды хранится в конфигурации как «7 09424B1D15041543595F».

Кроме того, чтобы все настроенные пароли имели длину не менее заданного значения, следует использовать команду **security passwords min-length** в режиме глобальной конфигурации. Например, после команды **security passwords min-length 8** любой новый пароль должен содержать не менее восьми символов.

Злоумышленники могут использовать программное обеспечение для взлома паролей для атаки грубой силы на сетевое устройство. Эта атака постоянно пытается угадать действительные пароли, пока они не сработают. Используйте команду **login block-for _#_ attempts _#_ within _#_** глобальной конфигурации для предотвращения такого типа атак. Команда **login block-for 120 attempts 3 within 60** будет блокировать попытки входа в систему в течение 120 секунд, если в течение 60 секунд произойдет три неудачных попытки входа.

Сетевые администраторы могут отвлечься и случайно оставить привилегированный сеанс EXEC открытым на терминале. Это может позволить внутреннему злоумышленнику изменить или стереть конфигурацию устройства.

По умолчанию ОС маршрутизатора завершает сеанс EXEC после 10 минут бездействия. Однако, этот параметр можно уменьшить с помощью команды конфигурации **exec-timeout** _minutes seconds_ line. Эту команду можно применить на консольные, вспомогательные и vty-линии. Например, команда **exec-timeout 5 30** на линиях vty отключает пользователя, если он бездействует 5 минут 30 секунд.

```
R1(config)# service password-encryption 
R1(config)# security passwords min-length 8 
R1(config)# login block-for 120 attempts 3 within 60
R1(config)# line vty 0 4 
R1(config-line)# password netlab123 
R1(config-line)# exec-timeout 5 30 
R1(config-line)# transport input ssh 
R1(config-line)# end 
R1# 
R1# show running-config | section line vty
line vty 0 4
 password 7 09424B1D15041543595F
 exec-timeout 5 30
 login
 transport input ssh
R1#
```

## Активация подключения по SSH

Telnet упрощает удаленный доступ к устройствам, но не является безопасным. Данные в пакете Telnet передаются в незашифрованном виде. Поэтому для обеспечения безопасного удаленного доступа настоятельно рекомендуется использовать на устройствах протокол SSH.

Настройка поддержки протокола SSH для устройства выполняется в шесть этапов.

**Шаг 1.** Устройство должно иметь уникальное имя узла, отличное от имени по умолчанию.

**Шаг 2.** Настройте имя IP-домена сети с помощью команды режима глобальной конфигурации **ip domain name**.

**Шаг 3.** Создайте пару ключей RSA устройства командой глобальной конфигурации **crypto key generate rsa general-keys modulus** _bits_. Этот ключ сервера SSH служит для проверки подлинности: по нему клиент убеждается, что подключился к нужному устройству. Сам трафик SSH шифруется сеансовыми ключами, которые клиент и сервер вырабатывают при обмене ключами в начале сеанса. Модуль определяет размер ключа RSA: чем он больше, тем ключ надежнее. На скорость передачи зашифрованного трафика размер ключа не влияет — больший ключ лишь дольше создается и немного замедляет установление сеанса. Используйте модуль не меньше 2048 бит: более короткие ключи RSA для подписи стандарт NIST SP 800-131A не допускает.

**Шаг 4.** Создайте учетную запись пользователя в локальной базе данных с помощью команды **username** в режиме глобальной конфигурации. В примере параметр **secret** используется так, чтобы пароль был зашифрован с помощью MD5.

**Шаг 5.** Используйте команду конфигурации **login local** строки для проверки подлинности строки vty в локальной базе данных.

**Шаг 6.** По умолчанию сеанс не разрешен на линиях vty. С помощью команды **transport input \[ssh | telnet\]** можно указать несколько  протоколов, включая Telnet и SSH.

Как показано в примере, маршрутизатор R1 настроен в домене span.com. Имя узла и имя домена дают имя пары ключей (R1.span.com), а значение модуля в команде **crypto key generate rsa general-keys modulus** задает ее размер — 2048 бит.

Затем создается запись локальной базы данных для пользователя с именем Bob. Наконец,  vty настроены на аутентификацию в локальной базе данных и могут принимать только входящие  SSH сессии. 

```
Router# configure terminal
Router(config)# hostname R1
R1(config)# ip domain name span.com
R1(config)# crypto key generate rsa general-keys modulus 2048
The name for the keys will be: R1.span.com % The key modulus size is 2048 bits
% Generating 2048 bit RSA keys, keys will be non-exportable...[OK]
Dec 13 16:19:12.079: %SSH-5-ENABLED: SSH 1.99 has been enabled
R1(config)#
R1(config)# username Bob secret netlab
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh
R1(config-line)# exit
R1(config)#
```

## Отключение неиспользуемых служб

Маршрутизаторы и коммутаторы запускаются с большим списком активных служб, которые могут потребоваться или не потребоваться при работе в сети. Отключите все неиспользуемые службы, чтобы сохранить системные ресурсы, такие как ЦП и ОЗУ, и предотвратить использование этих служб злоумышленниками. Какие службы включены по умолчанию, зависит от ОС и ее версии. Открытые порты можно проверить командой **show ip ports all**: в примере открыты только порты HTTPS и DHCP.

```
Router#show ip ports all
Proto Local Address               Foreign Address             State       PID/Program Name
TCB       Local Address               Foreign Address             (state)
tcp   :::443                     :::*                        LISTEN      309/[NetOS]HTTP CORE
tcp   *:443                      *:*                         LISTEN      309/[NetOS]HTTP CORE
udp   *:67                        0.0.0.0:0                               387/[NetOS]DHCPD Receive
Router#
```

В более ранних версиях ОС для этого используется команда **show control-plane host open-ports**: ее можно встретить на устройствах прежних поколений, а ее выходные данные аналогичны. Обратите внимание, что на этом маршрутизаторе работают небезопасный HTTP-сервер и Telnet. Обе эти службы должны быть отключены. Как показано в примере, отключите HTTP командой **no ip http server** в режиме глобальной конфигурации. Отключите Telnet, указав только SSH в команде конфигурации строки **transport input ssh**.

```
Router#show control-plane host open-ports
Active internet connections (servers and established)
Prot        Local Address      Foreign Address                  Service    State
 tcp                 *:23                  *:0                   Telnet   LISTEN
 tcp                 *:80                  *:0                HTTP CORE   LISTEN
 udp                 *:67                  *:0            DHCPD Receive   LISTEN
Router#configure terminal
Enter configuration commands, one per line.  End with CNTL/Z.
Router(config)#no ip http server
Router(config)#line vty 0 15
Router(config-line)#transport input ssh
Router(config-line)#end
*Mar  1 00:00:00.000: %SYS-5-CONFIG_I: Configured from console by console
Router#show control-plane host open-ports
Active internet connections (servers and established)
Prot        Local Address      Foreign Address                  Service    State
 udp                 *:67                  *:0            DHCPD Receive   LISTEN
Router#
```

Повторная команда **show control-plane host open-ports** показывает, что открытым остался только порт DHCP.
